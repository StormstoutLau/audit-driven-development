# v3.0 T19 — 跨模块契约确定性验证（import-linter 范本）实施方案

## 0. Context：为什么做这件事

ADD 自称最独有的护城河是「Spec↔Code 契约对齐」，但承担该能力的是 **7 个 LLM 透镜**（概率性判断）。经代码核对，**跨模块契约类断言目前没有任何确定性验证**：

| 事实 | 证据 |
|---|---|
| `classify_claim` 无 `contract` 类型 | [verify_findings.py L197-206](file:///f:/Coding/audit-driven-development/scripts/verify_findings.py#L197-L206)：只识别 `missing / wrong / violates / dead_code / import_related`（+ `taint` / `hallucination_pattern`），否则回落 `["generic"]`（L229） |
| 透镜产出的 `category: "contract"` 断言落 Tier 3 正则 | `verify_l4_structural` 仅对 `dead_code`（L511 前）与 `import_related`（L511-516）做结构化验证；其余走 `_verify_missing/_verify_wrong/_verify_violates` + generic 兜底（L527-544） |
| 契约类 check 完全缺位 | L541 generic 门条件 `if not checks and ("generic" in claim_types or "taint" in claim_types)` 中**没有** contract |
| 导入图能力**已存在但未被用于契约验证** | `ast_cfg.build_import_graph(repo_root)`（[L400-442](file:///f:/Coding/audit-driven-development/scripts/ast_cfg.py#L400-L442)，返回 `{module: [module,...]}`）+ `_parse_modules_from_claim`（L455+）+ `detect_cycle`（L332） |
| `guards.yml` 是**半死文件** | `merge_guards.py` 只按 `id` 合并（L22-33）、`spec_graph.resolve_guard_scopes()` 只解析 scope glob（L144-167）；**没有任何代码读取 `check` 字段执行校验**，且它是自由文本、本身不可机械执行 |

**目标**：新增 **Tier 2 确定性契约验证**（纯 stdlib），把「跨模块契约」断言从概率判断转为**可复算的结构裁决**。import-linter 仅作 **语义范本**（`layers` 顺序语义 + 间接依赖检测），**不作为依赖引入**。

## 2. 设计要点

### 2.1 新 claim 类型：`contract_related`

与既有 `import_related` 命名平行。识别判据（OR，**仅在 `_contract_enabled()` 为真时生效**）：

1. **结构化通道**：finding 顶层 `category == "contract"`（透镜产出的既有值），或 `evidence.analysis_kind == "contract"`（对齐 taint 的结构化通道写法，L211）
2. **文本通道（兜底）**：模块级预编译 `CONTRACT_PATTERNS` 命中 claim 文本（`layers?|layering|反向依赖|禁止依赖|跨模块|architectural boundary|cross-module|contract`）
   > 必须**模块级预编译**（项目禁令：函数内 `import re` 是反模式）

顺序上与既有类型**叠加不互斥**（`classify_claim` 本就是多标签语义）。

### 2.2 契约声明 schema（`guards.yml` 只增）

```yaml
guards:
  - id: "G101"
    description: "scripts/ 各层单向依赖：上层可依赖下层，反向禁止"
    scope: "scripts/**/*.py"          # 保留：人读标注 + 候选集（复用 resolve_guard_scopes）
    severity: "critical"              # 保留：缺省严重度
    check: "..."                      # 保留：自由文本，给 AI 用，不动
    contract:                         # ★ 新增，可选；缺失则该 guard 仍为纯 AI 约束
      kind: "layers"                  # 当前唯一取值（预留扩展）
      layers: ["a.b", "c.d", "e.f"]   # 顺序 = 高 → 低（前缀匹配模块名）
      allow: [["a.b", "e.f"]]         # 可选：显式豁免边（高→低白名单）
```

- **层序语义**：`layers[i]` **可**依赖 `layers[j]`（j>i）；`j<i` 即违规 —— 与 import-linter `layers` 语义一致，但自实现。
- **间接依赖**：在模块图上**存在**从高到低的传递路径即违规（非仅直连边）。
- **层↔模块映射**：用 `layers[k]` 作为**模块名前缀**匹配（不引入 glob 依赖）；`scope` 仅作人读标注与候选集。
- **severity 映射沿用既有约定**：`blocker→P0 / critical→P1 / warning→P2 / info→P3`（[guards.template.yml L5](file:///f:/Coding/audit-driven-development/docs/audit/guards.template.yml#L5)）。
- **加载路径探测顺序**：`docs/audit/guards.yml` → `docs/audit/guards.project.yml` → `docs/audit/guards.common.yml` → `None`。

### 2.3 三态裁决语义（**核心**）

给定「claim 中解析出的模块对 + 方向」与「声明的 layers 契约 + 实际导入图」：

| 状态 | 成立条件 | 后果 |
|---|---|---|
| **`verified=True`** | 声明合法 ∧ 相关模块均在图中 ∧ **claim 断言的不良依赖确实存在**（图上存在被禁方向/层序违规路径，且不命中 `allow`） | `level=4`，结构化确认 |
| **`verified=False`** | 声明合法 ∧ 模块均在图中 ∧ **断言的依赖不存在，或存在但被 `allow` 豁免** | `tier=2`，结构化证伪 ⇒ 依 ADR-018 **移除**（`disproof_action` 默认 `remove`，**不需改** `structural_false` L998-1002） |
| **`verified=None`** | **其余全部情形**（见 §4） | **不写入该 check** ⇒ 回落 generic（Tier 3）⇒ 交由既有路径裁决。**绝不静默判 False** |

> **None 的硬理由**：沿用 taint 的教训（`sink_nodes == 0` 与"无路径"同形 ⇒ 必返回 None）。图不完整与"确实无依赖"在数值上同形，**因此必须以 None 表达不确定性，不得落入 False**。

### 2.4 kill switch 与逐位一致

- `ADD_CONTRACT_DISABLE=1` ⇒ **识别与分派全域关闭**（`classify_claim` 不打标签、L4 不进 contract 分支）。
- 新字段（3 个：`contract_verified` / `contract_kind` / `contract_rule_id`）**仅在该 finding 被分类为 `contract_related` 时写入** ⇒ 关闭态与 v3.0-T9' 现状**逐位一致**（同 AC-21/E-6 模式）。
- **不新增 CLI 参数**（避免参数面膨胀；taint 的 `--taint-disproof` 是特例，contract 无此需求）。

## 4. 边界与风险处理（**全部 → `None`，绝不判 False**）

| # | 边界 | 策略 |
|---|---|---|
| 1 | **不可构建 / 语法错误文件** | `build_import_graph` 已静默 `continue` 跳过（L427-428）⇒ 层内模块可能缺失 ⇒ 归入「图不完整」⇒ `None` |
| 2 | **循环导入 / 含环图** | BFS 用 visited 集，保证终止；**环本身不构成层违规证据**，只按声明判方向 |
| 3 | **动态 import**（`__import__` / `importlib.import_module`） | AST 不可见 ⇒ 命中该模式时对涉及模块返回 `None`（标记 `graph_incomplete`），**勿判 False** |
| 4 | **命名空间包**（无 `__init__.py`） | `_resolve_module` L387-397 返回 `None` ⇒ `None` |
| 5 | **跨包相对导入**（`from . import x` / `from ..pkg import y`） | `build_import_graph` L437 的 `if node.module:` **会丢弃 `node.module is None` 的节点** —— 已知缺口；由 `resolve_relative` 补解析，**无法解析则 `None`**（否则会把内部依赖误当外部 ⇒ **假 False**） |
| 6 | **声明与 scope 脱耦**（层前缀 ≠ scope glob） | `layers` 前缀是唯一权威；`scope` 仅标注；不一致**不报错**，按前缀执行并记入 evidence |
| 7 | **新识别导致 benchmark 漂移** | 先**实测** `category=="contract"` 在 882 条语料中的占比；用 `ADD_CONTRACT_DISABLE=1` 做 **A/B 非退化门**（ΔP = ΔR = ΔF1 = 0），并披露「触发面大小 + 是否真正进入被测分支」（对齐 taint AC-8「休眠通过」的教训） |
| 8 | **声明缺失 / YAML 非法 / 层声明非法**（空、重复、非连续） | 分别 ⇒ `None`；YAML 解析失败**不得抛异常**（沿用 `spec_graph.py` 可选 import 风格，L148-151） |
