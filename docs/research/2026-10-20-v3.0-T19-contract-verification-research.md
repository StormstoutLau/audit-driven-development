## 2. 语义范本：import-linter（借语义，不借依赖）

调研确认 import-linter 的两个机制值得借用（**仅作语义范本**，不作为依赖引入）：

| 机制 | 语义 | 采纳方式 |
|---|---|---|
| **`layers` 契约** | 声明层的**有序**列表；`layers[i]` 可依赖 `layers[j]`（j>i），反向禁止 | 自实现：层序数组 + 前缀匹配模块名 |
| **间接依赖检测** | 违规不限于直连边，**传递路径**同样违规 | 自实现：模块图上的 BFS 可达性（而非仅查直连边） |

**不采纳**：import-linter 的 `.importlinter` ini 格式（与 ADD 自身规则体系不统一）、其作为 pip 依赖（ADR-023）。依据见 [补强调研报告 §12](file:///f:/Coding/audit-driven-development/docs/research/2026-10-20-ADD-v3.0-reinforcement-research.md)。

## 4. 本仓库补测（原始数值，可复现）

### F-1｜`build_import_graph` 的作用域敏感性（**最重量级发现**）

```
py -c "import sys; sys.path.insert(0,'scripts'); import ast_cfg; \
        print(len(ast_cfg.build_import_graph('.')), sum(len(v) for v in ast_cfg.build_import_graph('.').values()))"
```

| `repo_root` | 模块数 | 内部依赖边 | 判定 |
|---|---|---|---|
| `.`（仓库根） | **2164** | **0** | ⚠️ **静默退化** —— 无异常、无报错，但语义为空 |
| `scripts` | **54** | **41** | ✅ 有效图 |

**根因**：`_resolve_module` 把导入名**相对 `repo`** 解析，隐含假设「模块名相对该根扁平」。在仓库根，`scripts/verify_findings.py` 的模块名是 `scripts.verify_findings`，而它的 `import verify_findings` 会去找 `./verify_findings.py` ⇒ 全部落为外部依赖。

**危害（必须阻断）**：0 边图会让**任何**违规断言都得到「不存在反向路径」⇒ 判 **`False`** ⇒ 即「**假 False**」。这正是本项目已有教训的同型问题（taint 的 `sink_nodes == 0` 与"无路径"数值同形）。

**对策**：契约声明新增**显式图根** `root:` 字段（默认 = repo 根），且验证器必须加**图完整性哨兵**：`模块数 > 1 且内部边 == 0` ⇒ `graph_incomplete` ⇒ 返回 `None`。

### F-2｜`scripts/` 真实依赖边（用于构造真实用例）

41 条内部边中与本任务相关的实边：

```

joern_cpg              -> _script_utils

```

⇒ 可构造一条**真实且成立**的分层契约（见 Step 9 的 `docs/audit/guards.yml`），无需伪造。

### F-3｜语料层实测：`category` 与 `analysis_kind` **整体不存在**

```
扫描 docs/benchmark/**/findings*.json → 8 个文件、总计 882 条 finding
category 分布：None × 882        （100% 缺该字段）
evidence.analysis_kind：None × 882
样例 keys：['claim','dimension','evidence','id','severity']
```

⇒ **结构化通道（`category == "contract"` / `evidence.analysis_kind == "contract"`）在当前 882 条语料上命中 = 0**。该通道仅经**透镜/Subagent 管线**（`ModuleAuditResult` schema）与合成测试可达 —— 与 taint 通道 A（`evidence.cwe` 零命中）**完全同型**。

### F-4｜文本通道：**4 / 882 = 0.45%，且 4 条全是偶然子串命中**

```
正则（计划初稿）：layers?|layering|反向依赖|禁止依赖|跨模块|architectural boundary|cross-module|contract
命中 4 条：bigvul/findings.json ×2、bigvul/findings_nonlinux.json ×2
命中内容：
  "...The ape_read_header function in ape.c in libavformat in FFmpeg before..."
  "...SQL injection vulnerability in the msPostGISLayerSetTimeFilter function..."
```

**逐条判定**：`msPostGISLayerSetTimeFilter` 命中 `layers?`（`Layer` 子串）；两条 ape.c 条目命中 `contract` 词（`libavformat in FFmpeg befo**...**` 一类的普通词）⇒ **4 条全部为噪声，无一条是真实契约断言**。

**对策（实证修正）**：正则必须**收紧**——加词边界、**移除裸 `layers?` 与裸 `contract`**、改用中文/短语型模式（如 `层序|分层契约|反向依赖|禁止依赖|跨模块依赖|layer violation|cross-module dependency|architectural boundary`）。最终值须在 Step 9 用**实现后的正则**复测并如实披露（沿用 taint C-2 的教训：早期宽松正则估计会系统性偏高）。
