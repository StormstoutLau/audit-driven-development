## 0. 背景与问题陈述

### 0.1 要修复的短板

T19 与 T9' Phase 1 都已交付并通过验收，但在自有 benchmark（882 条）上**实际裁决面 ≈ 0**。T19 将其记为 R-1「收益待 T12 引入 SAST 转换器语料」。本步实测证明该诊断**不完整**：

| 门 | 实测事实 | 来源 |
|---|---|---|
| **门 1：无 `category` 生产者** | 六个转换器全部写 `dimension`，**无一写 `category`**；882/882 缺该字段 | F-1 / F-3 |
| **门 2：`l4_eligible` 结构性屏蔽** | **855/882（96.9%）为 `False`**；仅 27 条（3.1%）缺省可进 L4；语料中**零条** semgrep/codeql 产物 | F-6 |
| 旁证：`dimension` 是死元数据 | 10 种取值、无枚举约束、无消费者 | F-2 / F-3 |

⇒ 结论：**schema 对齐是 T12 的硬前置**；只扩语料无法激活任何结构化通道。

### 0.2 战略定位约束

- ADD = **验证层**（ADR-001），不自建 detection ⇒ 本步不新增任何检测能力。
- 本项目**不生产** finding 的"检测事实"，只生产"验证裁决"；因此本步的产出必须是 **schema 契约 + 校验器 + 保守映射**，而非新的分析引擎。
- 零新增 runtime 依赖（ADR-023）⇒ 校验器必须纯 stdlib，**不引入 `jsonschema`**。

### 0.3 本步解决的三个设计缺口

| ID | 缺口 | 现状 |
|---|---|---|
| **GAP-1** | 两套互不兼容的 finding 形态（canonical `AuditFinding` vs 转换器产物） | `schemas/audit-finding.schema.json` 要求 8 必填字段且 `additionalProperties:false`；转换器产物缺 4 项且带 `dimension`/`l4_eligible` |
| **GAP-2** | `category` 无任何生产者 | 消费者已就绪（verify_findings L1018 / issues_tracker L43 / inter_rater L117），生产者为零 |
| **GAP-3** | 缺字段导致**现网异常**与**静默失真** | `issues_tracker.py:L43` 强取 ⇒ KeyError；`inter_rater.py:L117` 静默归 `unknown` |

## 1. 设计决策

### D-T20-1: **分层 schema** —— `AuditFinding` 不动，新增 `SastFinding`

- **决策**: 保留 [schemas/audit-finding.schema.json](file:///f:/Coding/audit-driven-development/schemas/audit-finding.schema.json) **逐字节不变**（审计透镜产物：有 `spec_ref` / `confidence` / `fix_cost`）；**新增** `schemas/sast-finding.schema.json` 描述工具产物（可含 `dimension` / `l4_eligible` / 工具元数据）。
- **理由**:
  1. `confidence` 是反幻觉链路的核心语义（high=grep+AST / medium=grep / low=推断）。**转换器没有"置信度"概念**，填任何值都是编造 ⇒ 不能强行统一（调研 §4 方案 A 被否的决定性理由）。
  2. `spec_ref` 同理：SAST 工具不指向设计文档章节。
  3. 收紧 canonical schema 会削弱既有"evidence 必填"约束（那是反幻觉基石），且会让 882 条既有语料瞬间"非法"⇒ 方案 C 被否。
- **后果**: 两份 schema 并存；`SastFinding` 只用于**工具产物**校验，不用于 Phase 4 状态机输入（后者仍要求 canonical）。
- **追溯**: F-1 / F-4 / S-2 / X-5

### D-T20-2: `category` 的生产者 = **显式声明**（lens 或规则元数据），**不做任何猜测映射**

- **决策**:
  1. **透镜通道（权威）**: Phase 2 lens 产物按 canonical schema 写 `category`（含 `contract`）。此为 SKILL.md 既有定义，本步只**强化契约与校验**，不新造语义。
  2. **转换器通道（受限）**: 仅当**上游规则显式携带**审计类别标注时透传 —— Semgrep `extra.metadata.add_category`（值须 ∈ canonical 5 值枚举）。**未标注 ⇒ 省略字段**。
  3. **v1 内置映射表为空**：明确**不**把 `metadata.category: security` 映射为 `behavior`。
  4. **CodeQL 侧暂不支持 `category` 透传**（H2 修正）：CodeQL 无与 `metadata.add_category` 等价的官方字段；**不得**凭空发明 `properties.add_category`。若将来确有需求，需先取得一手来源再单独立项。
- **理由**:
  - 上游 category（security/correctness/…）是**领域**标签，与审计透镜的**判断类型**不同轴（F-2 已证 `dimension` 出现 10 种失控取值）⇒ 强行映射制造假精确（R-1）。
  - 保守省略的代价是"该 finding 不被契约通道识别"，等价于今日行为；而错误映射的代价是**假裁决进入修复基线**（依 ADR-018 会被移除）⇒ 非对称风险，必须选保守侧。
- **后果**: T19 的 `contract` 通道**只能**由透镜产物激活 ⇒ 验收必须有 golden case（D-T20-5）。
- **追溯**: X-2 / X-5 / R-1 / S-1 / S-3

### D-T20-3: `analysis_kind` 只在**工具确实提供数据流证据**时写入

- **决策**:
  - Semgrep：`result.extra.dataflow_trace` **存在** ⇒ `evidence.analysis_kind = "taint"`；不存在 ⇒ **省略**。
  - CodeQL：SARIF `result.codeFlows` **存在** ⇒ 同上；不存在 ⇒ 省略。
  - **禁止**由 `check_id` / `ruleId` / 名称子串推断（如含 `injection` 就判 taint）。
- **理由**: X-3 表明 CE 的 `dataflow_trace` 无官方保证 ⇒ 不能把它作为必需输入，但**确实存在时**它就是最强的结构化证据；而按名称推断等于用命名当语义，会产生系统性误判（T9' 的 `TAINT_PATTERNS` 已证明"更宽的模式 = 更多噪声"）。
- **后果**: 在 CE 不输出该字段时，T9' 结构化通道仍休眠 —— 这是**已知且诚实**的边界，不得用启发式掩盖。
- **追溯**: X-3 / V-10 / R-4 / S-4

### D-T20-4: 新增 `scripts/validate_findings.py`（纯 stdlib，**真实解释 schema 文件**）

- **决策**: 实现 draft-07 的**受限子集**解释器：`type` / `required` / `enum` / `pattern` / `minimum` / `minLength` / `items` / `properties` / `additionalProperties` / `$ref`（文档内） / `$schema` / `$id`。
- **理由**: 若把校验规则硬编码进脚本，schema 文件就变成**装饰品**（等同 T19 已识别的"dead parameter"反模式）；解释 schema 文件才能让"schema 是契约"这件事成立。子集化是可控成本（无外部依赖）。
- **后果**: 不支持的 draft-07 关键字必须**显式报错**（`unsupported keyword`，退出码 2）而非静默忽略 —— 否则又会制造"看起来校验了其实没校验"。
- **追溯**: ADR-023 / S-5 / R-2

### D-T20-5: **golden case** 是"激活"的唯一验收判据

- **决策**: 新增一个 **fixture**（非伪造语料，明确标注 synthetic）：一条符合 canonical `AuditFinding` 的 finding，`category="contract"`、`claim="verify_findings imports ast_cfg"`（方向与 `guards.yml` 五层一致），端到端跑 `verify_findings`，断言 `contract_verified is not None`。
- **理由**: R-6 —— 若只有 schema 而无端到端裁决，本步只算"schema 就绪"，不能声称"能力激活"。
- **后果**: 该 fixture 与 T19 的 `test_T3_30`（真实 repo 用例）互补：前者验**生产者→消费者**链路，后者验**真实仓库契约**。
- **追溯**: R-6 / S-7

### D-T20-6: `l4_eligible` 与 `dimension` **只增不删、语义不动**

- **决策**: 不改写 855 条 `l4_eligible=False`，不把 bigvul/cvefixes 的开关翻成 `True`（它们确无结构化支持）；`dimension` 原样保留，**不**与 `category` 互转。
- **理由**: 翻开关会让 C/C++/Java finding 进入不支持的 L4 路径，产生假裁决；`dimension` 改名会破坏 `guards.yml` 的 `audit_lens` 语义（`spec_graph.py:L164` 读 `guard.get("category","behavior")`，与 finding 字段同名但不同轴）。
- **后果**: 语料层面 Δ 仍为 0 ⇒ **验收必须分层披露**（见 AC-17）。
- **追溯**: F-6 / R-5 / S-1

### D-T20-7: 修复缺失字段的**消费端**（KeyError 与静默失真）

- **决策**:
  - `issues_tracker.py`：`finding["category"]` → `finding.get("category") or "unknown"`（两处）。
  - `inter_rater.py`：`unknown` 桶**显式计入输出**（不静默吞掉），并在 `--per-dimension` 输出中单独列出。
  - **不改** `verify_findings.py` 的既有读取逻辑（其 `.get("category")` 已是安全的）。
- **理由**: 缺字段是**数据现实**，消费端必须容忍；而"静默归 unknown"会让人误以为分组有效。
- **追溯**: V-4 / V-5 / F-3 / S-6 / R-3

### D-T20-8: 新增 **ADR-029**（本步是架构性决策）

- **决策**: 登记 `ADR-029: Findings schema 分层（AuditFinding = 审计判断 / SastFinding = 工具事实）`，含 Confirmation 段（可机器校验的断言）。
- **理由**: 双 schema 是长期架构约定；ADR 的 `Confirmation` 段可绑定 `validate_findings` 作为 CI 校验点（借 MADR 范式，调研 §7 #16）。
- **追溯**: 调研 §7 #16

## 2. 语义与接口

### 2.1 `schemas/sast-finding.schema.json`（新增）

```json
{
  "$schema": "https://json-schema.org/draft-07/schema",
  "$id": ".../schemas/sast-finding.schema.json",
  "title": "SAST Finding Schema (tool-produced)",
  "type": "object",
  "required": ["id", "severity", "claim", "evidence"],
  "properties": {
    "id":        { "type": "string", "minLength": 1 },
    "severity":  { "enum": ["P0", "P1", "P2", "P3"] },
    "claim":     { "type": "string", "minLength": 1 },
    "category":  { "enum": ["signature", "behavior", "corrective", "blind_spot", "contract"] },
    "dimension": { "type": "string", "minLength": 1 },
    "l4_eligible": { "type": "boolean" },
    "evidence": {
      "type": "object",
      "required": ["file", "line_start"],
      "properties": {
        "file":          { "type": "string", "minLength": 1 },
        "line_start":    { "type": "integer", "minimum": 1 },
        "line_end":      { "type": "integer", "minimum": 1 },
        "cwe":           { "type": "string" },
        "owasp":         { "type": "string" },
        "rule_id":       { "type": "string" },
        "source":        { "type": "string" },
        "analysis_kind": { "enum": ["taint"] }
      },
      "additionalProperties": true
    }
  },
  "additionalProperties": false
}
```

**关键点**：
- `category` **不在 required**（不可映射即省略）；
- `dimension` / `l4_eligible` **是合法字段**（承接既有产物，只增不删）；
- `evidence.analysis_kind` 只允许 `"taint"`（当前唯一有语义的取值）；
- **`evidence.additionalProperties: true`（H1 修正）**：`evidence` 是**工具溯源容器**，其内容随工具而异。实测 882 条语料出现 **11 个** evidence 键（`file` 882 / `line_start` 882 / `commit_hash` 805 / `project` 779 / `repo_local_path` 152 / `file_fix_status` 53 / `repo_url` 26 / `commit_hash_source` 22 / `commit_hash_original` 22 / `file_fix_original` 17 / `file_fix_func_name` 17）。若收紧为 `false`，**AC-2 直接不可达**（882 条全违规）。⇒ 严格性放在**顶层**（防字段漂移），宽容性放在 `evidence`（容纳工具溯源）。

### 2.2 接口：`validate_findings.py`

| 项 | 定义 |
|---|---|
| 签名 | `validate(findings: list[dict], schema: dict) -> list[str]`（返回错误消息列表，空 = 通过） |
| CLI | `python scripts/validate_findings.py --findings <path> --schema <sast\|audit\|path> [--json]` |
| `--schema` 简写 | `sast` ⇒ `schemas/sast-finding.schema.json`；`audit` ⇒ `schemas/audit-finding.schema.json`；否则按路径 |
| 退出码 | `0` = 全部通过 · `1` = 有违规 · `2` = 用法/schema 加载/不支持的关键字 |
| 输出 | 每条形如 `<finding_id>: <json_pointer> <message>`；`--json` 输出结构化列表 |

### 2.3 转换器映射规则（v1）

| 上游证据 | 输出字段 | 说明 |
|---|---|---|
| Semgrep `extra.metadata.add_category` ∈ 5 值枚举 | `category` | 显式声明才透传 |
| Semgrep `extra.metadata.add_category` 越界/缺失 | **省略 `category`** | 不猜测、不降级为 `behavior` |
| Semgrep `extra.dataflow_trace` 存在 | `evidence.analysis_kind = "taint"` | 存在即证据 |
| CodeQL `result.codeFlows` 存在 | `evidence.analysis_kind = "taint"` | 同上 |
| `dimension` | 原值透传 | 不动 |
| `l4_eligible` | 原值透传 | 不动 |

### 2.4 `None` / 省略的完整语义

| 情况 | 结果 | 下游行为 |
|---|---|---|
| `category` 省略 | finding 不被 contract 通道识别 | 与今日**逐位一致**（AC-4） |
| `analysis_kind` 省略 | taint 结构化通道不激活 | 回落文本 `TAINT_PATTERNS`（今日行为） |
| `category` 非法值（如 `"security"`） | **校验失败**（退出码 1），但运行时不崩 | 数据质量门拦截，不进入运行时判断 |
| schema 不支持的关键字 | 校验器退出码 2 | 必须修校验器或 schema，**不得静默忽略** |

## 4. 风险与阻断项

| # | 风险 | 缓解 |
|---|---|---|
| **B-1（阻断）** | 校验器解释器与 draft-07 语义有偏差，产生"假通过" | 用本机 882 条真实语料 + 8 个定向负样本（缺必填/类型错/枚举越界/多余字段/`$ref` 断链/pattern 不符/minimum 越界/不支持关键字）双向验证 |
