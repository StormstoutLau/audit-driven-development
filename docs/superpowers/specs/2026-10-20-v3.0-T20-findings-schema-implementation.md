## 2. `schemas/sast-finding.schema.json`（全文）

```json
{
  "$schema": "https://json-schema.org/draft-07/schema",
  "$id": "https://github.com/StormstoutLau/audit-driven-development/schemas/sast-finding.schema.json",
  "title": "SAST Finding Schema (tool-produced)",
  "description": "Tool-produced findings (converters). category is OPTIONAL: only emitted when the upstream rule explicitly declares it. evidence is an open container for tool provenance.",
  "type": "object",
  "required": ["id", "severity", "claim", "evidence"],
  "properties": {
    "id":          { "type": "string", "minLength": 1 },
    "severity":    { "enum": ["P0", "P1", "P2", "P3"] },
    "claim":       { "type": "string", "minLength": 1 },
    "category":    { "enum": ["signature", "behavior", "corrective", "blind_spot", "contract"] },
    "dimension":   { "type": "string", "minLength": 1 },
    "l4_eligible": { "type": "boolean" },
    "evidence": {
      "type": "object",
      "required": ["file", "line_start"],
      "properties": {
        "file":          { "type": "string", "minLength": 1 },
        "line_start":    { "type": "integer", "minimum": 1 },
        "line_end":      { "type": "integer", "minimum": 1 },
        "cwe":           { "type": "string" },
        "owasp":         { "type": "string" },
        "rule_id":       { "type": "string" },
        "source":        { "type": "string" },
        "analysis_kind": { "enum": ["taint"] }
      },
      "additionalProperties": true
    }
  },
  "additionalProperties": false
}
```

**设计自检**：
- 顶层 `additionalProperties:false` ⇒ 新增字段必须显式声明（防 `dimension` 式词表失控重演）；
- `evidence` 开放 ⇒ 容纳 `commit_hash`/`project`/`repo_url`/`file_fix_*` 等 11 个实测键（H1）；
- `category` 不在 `required` ⇒ 缺失合法（AC-4 逐位一致的前提）。

## 3. `scripts/validate_findings.py`

### 3.1 模块结构

```python
"""v3.0 T20: Findings schema 校验器（纯 stdlib，零新增依赖）。

解释 JSON Schema draft-07 的受限子集；遇到不支持的关键字必须报错（退出码 2），
不得静默忽略 —— 否则 schema 会退化为装饰品。
"""

SUPPORTED_KEYWORDS = frozenset({
    "$schema", "$id", "title", "description",
    "type", "required", "enum", "pattern", "format",
    "minimum", "maximum", "minLength", "maxLength",
    "minItems", "maxItems", "items",
    "properties", "additionalProperties", "definitions", "$ref",
})
SUPPORTED_FORMATS = frozenset({"date"})
```

### 3.2 接口

| 函数 | 签名 | 职责 | 复杂度 |
|---|---|---|---|
| `load_schema` | `(path: str) -> dict` | 读 JSON；非 dict 或解析失败 ⇒ `SchemaError` | O(size) |
| `resolve_ref` | `(root: dict, ref: str) -> dict` | 仅支持 `#` 与 `#/definitions/<name>`；其余 ⇒ `SchemaError` | O(1) |
| `validate` | `(value, schema, root=None, path="$") -> list[str]` | 递归校验，返回错误消息列表（空 = 通过）；`root` 用于 `$ref` 解析 | O(fields) |
| `check_keywords` | `(schema) -> None` | 递归扫描 schema 中不支持的关键字 ⇒ `SchemaError` | O(schema) |
| `validate_file` | `(findings_path: str, schema: dict) -> list[str]` | 读文件 → `_extract_findings()` → 逐条校验；消息前缀含 finding `id` | O(N·F) |
| `_extract_findings` | `(data) -> list[tuple[dict, str]]` | **三种形态**（G-1 修正）：① `list` ⇒ 元素；② `dict` 含 `findings` ⇒ 该列表；③ `dict` 含 `module_results`/`cross_module_results` ⇒ **展平两者**（canonical `AuditReport`）；其他 ⇒ `SchemaError` | O(N) |
| `main` | `(argv=None) -> int` | CLI；返回退出码 | — |

> **G-1 说明**：`schemas/example-audit-report.json` 是 **AuditReport**（findings 在 `module_results[].findings`），不是 `{"findings":[...]}`。若只支持前两种形态，`--schema audit` 会**校验 0 条并静默通过**（假绿）。形态 ③ 是必需的。

### 3.3 校验语义（逐关键字）

| 关键字 | 语义 | 备注 |
|---|---|---|
| `type` | `object`/`array`/`string`/`integer`/`number`/`boolean` | **`bool` 不算 `integer`**（Python 陷阱，必须显式排除） |
| `required` | 键**存在**即通过（不要求真值） | `None` 值视为存在 |
| `enum` | 精确成员判断 | 大小写敏感 |
| `pattern` | `re.search`（**非** `fullmatch`） | 模块级预编译缓存 |
| `minimum` / `maximum` | 数值比较 | 非数值类型先报 `type` 错，不再比较 |
| `minLength` / `maxLength` | 字符串长度 | — |
| `minItems` / `maxItems` | 数组长度 | — |
| `items` | 对每个元素应用子 schema | 仅支持单 schema（不支持 tuple 形式） |
| `properties` | 对**存在**的键应用子 schema | 缺失不报错（由 `required` 管） |
| `additionalProperties` | `false` ⇒ 未在 `properties` 中的键报错；`true`/缺省 ⇒ 允许；**schema 形式 ⇒ 对每个未知键应用该子 schema**（G-4 修正） | canonical schema 的 `summary.module_scores` 用的正是 schema 形式；不支持则 `--schema audit` 直接 exit 2 |
| `format: date` | `YYYY-MM-DD` 且为合法日期 | 其他 format ⇒ `SchemaError` |
| `$ref` | 文档内 `#/definitions/X` | 循环引用 ⇒ `SchemaError` |

### 3.4 错误消息格式

```
<source>:<index> <finding_id> <jsonpath>: <message>
```

示例：
```
docs/benchmark/bigvul/findings.json:0 BV-0001 $.severity: value 'HIGH' not in enum ['P0','P1','P2','P3']
schemas/example-audit-report.json#module_results[0]:0 BRIDGE-P0-1 $.category: ...
```

> **G-5 修正**：`AuditReport` 形态下前缀需带「哪个模块数组 + 索引」，否则 5 条 finding 的同名路径无法定位。

### 3.5 CLI

```
python scripts/validate_findings.py --findings <path> [<path> ...] [--schema sast|audit|<path>] [--json] [--quiet]
```

| 退出码 | 含义 |
|---|---|
| `0` | 全部通过 |
| `1` | 存在违规（逐条打印） |
| `2` | 用法错误 / schema 加载失败 / **不支持的关键字** |

`--schema` 简写解析：`sast` → `schemas/sast-finding.schema.json`；`audit` → `schemas/audit-finding.schema.json`；否则按路径。

### 5.2 `scripts/inter_rater.py`（改 2 处，含**已发现的默认值不一致缺陷**）

**缺陷事实**：`compute_per_dimension_kappa()` 中，收集类别用 `.get("category", "unknown")`（L117），而分组过滤用 `.get("category", "")`（L125 / L131）⇒ **`unknown` 桶永远为空**（缺 category 的 finding 永远不会被计入任何桶，包括 `unknown`）。

**改点 1 —— 统一访问器（新增模块级 helper）**：

```python
def _finding_category(f):
    """v3.0 T20: 统一 category 取值口径（缺失 ⇒ 'unknown'），消除 default 不一致。"""
    if not isinstance(f, dict):
        return "unknown"
    return f.get("category") or "unknown"
```

L117 / L125 / L131 三处统一改为 `_finding_category(f)`。

**改点 2 —— 显式 `unknown` 桶**（插入位置明确：**L139 `return result` 之前**，G-3）：

```python
    # v3.0 T20: unknown 桶恒存在（即使无数据），避免"分组看起来完整"的静默失真
    result.setdefault("unknown", {"kappa": None, "agreement_rate": None,
                                  "matrix": None, "note": "findings with missing category"})
    return result
```

> 语义：`unknown` 桶**恒存在**且带显式 `note`，避免"看起来分组完整其实漏了一整类"的静默失真（AC-15）。
