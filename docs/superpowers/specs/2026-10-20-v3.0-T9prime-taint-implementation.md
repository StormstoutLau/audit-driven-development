## 0. 全局工程约束

### 0.1 Python 版本与依赖

| 项 | 要求 | 说明 |
|---|---|---|
| Python 版本 | **≥ 3.9** | 不使用 3.10+ 的 `match/case`、`X | Y` 类型联合、`dict |` 合并 |
| 新 runtime 依赖 | **零** | 不引入 tree-sitter / javalang / 任何 pip 包（[ADR-023](file:///f:/Coding/audit-driven-development/docs/DECISIONS.md#L525)） |
| 仅标准库 | `ast` / `re` / `os` / `subprocess` / `hashlib` / `time` / `json` / `tempfile` / `deque`（`collections`） | 均为 Python 3.9 内置 |
| 可选外部依赖 | Joern CLI ≥ 4.0 + JDK | **可选**；不可用时三态降级（既有约定） |
| TDD 框架 | `pytest`（测试期依赖，非 runtime） | 运行命令用 `py -m pytest`（默认 `python` 无 pytest，见 AC-10 实测） |

### 0.2 性能预算

| 场景 | 预算 | 依据 |
|---|---|---|
| 单 finding taint **识别**开销 | **0**（`"taint" not in claim_types` 时零额外路径） | 分支短路 |
| 单 finding Tier 1（CPG 已缓存） | ≤ **3 s** | 设计 spec §5「性能上限（设计目标）」 |
| 单 finding Tier 1（CPG 未缓存） | ≤ `JOERN_TIMEOUT_SEC` = 30 s，**每 repo 仅 1 次** | [joern_cpg L40](file:///f:/Coding/audit-driven-development/scripts/joern_cpg.py#L40) |
| 单 finding Tier 2（AST 解析 + def-use） | ≤ **50 ms**（**估计值，非实测**） | 与既有 `verify_dead_code` Tier 2 同量级（单文件 `ast.parse` + O(N log N) 传播）；由 AC-14 计时断言兜底 |
| 单 finding Tier 3（正则） | ≤ **1 ms**（**估计值，非实测**） | 既有量级 |
| 全量 882 findings 增量 | ≤ **+3%**（**设计目标，非实测**；触发面实测为 **19/882 = 2.2%**） | 触发面来自裁决分析 E-3 实测；耗时增量由 AC-8/AC-14 兜底 |

**关键性能保护（必须实现）**：
1. **CPG 复用**：taint 与 dead_code / import **共用同一 CPG**（`_get_cache_key(repo_root, language)` 已 language-scoped）⇒ 不因 taint 新增 CPG 构建。断言见 T2.9 / AC-18。
2. **查询级 memo**：同一 `(cache_key, sink_file, sink_line, source_line, language)` 的 Tier 1 查询结果**只执行一次**（§4.2.4）。CPG 子进程是唯一昂贵环节。
3. **无 O(n²)**：所有遍历为 O(V+E)（`is_reachable` 已是 BFS + `deque`）；不得引入 `list.pop(0)` 或嵌套全表扫描。

### 0.3 向后兼容硬规则（不可违反）

1. **新参数一律带默认值**：`classify_claim(claim, evidence=None)`、`verify_l4_structural(..., evidence=None, taint_disproof=None)`、`verify_taint_flow(...)` 的 `source_file/source_line=None`、CLI `--taint-disproof` 默认 `downgrade`。既有调用方零改动。
2. **schema 只增不删**：新增 `taint_verified` / `taint_mode` / `taint_disproof_action`（finding 级）与 `checks["taint"]` 内部字段；**不改既有字段名与类型**。
3. **`evidence=None` 时结构化通道不激活**（D-T9'-1 v1.2 不变式）。
4. **kill switch 双向可逆**：`ADD_TAINT_DISABLE=1` ⇒ taint 识别与分派**全域关闭**，全量裁决与 v2.8 逐位一致（AC-9）。这是 v2.8 一致性的**唯一承载者**（非 `evidence=None`）。
5. **`verification_level` 数值域保持 `1..4`**，不出现 5（AC-11 / [ADR-027](file:///f:/Coding/audit-driven-development/docs/DECISIONS.md#L615)）。
6. **不抛异常**：taint 全链路遵守 [joern_cpg L4-L5 模块约定](file:///f:/Coding/audit-driven-development/scripts/joern_cpg.py#L4-L5)（"module NEVER raises"）；异常 → `verified=None`。
7. **新增字段的写入时机（工程裁定）**：`taint_verified` / `taint_mode` / `taint_disproof_action` **仅在该 finding 被分类为 taint（`"taint" in claim_types`）时写入**。理由：kill switch 关闭时 taint 分类不发生 ⇒ 不写字段 ⇒ AC-9 逐位一致不被破坏；同时避免给 882 条非 taint findings 注入 3 个 `null` 字段的膨胀。（见 §2 E-6）

### 0.4 低效操作排除清单（禁止 / 必须）

| 反模式 | 修正 | 原因 | 检查项 |
|---|---|---|---|
| 函数内 `import re` | 模块级 `import re` + **预编译**（`TAINT_PATTERNS` / `_TAINT_SINK_RE`） | 每次调用重编译正则 | §9 自检 |
| 重复构建 CPG | 复用 `_get_cache_key` + `_generate_cpg` 缓存 | 子进程开销 ~秒级 | T2.9 |
| 同一 sink 重复跑 Joern | `_TAINT_QUERY_MEMO`（有界） | 子进程开销 ~秒级 | T2.8 |
| 同一文件重复 `ast.parse` | **接受**（与既有 dead_code Tier 2 一致，单次 ≤50ms）；不引入跨 finding 文件缓存 | 保持行为一致性优先于微优化 | §2 E-7 |
| 循环内 `open()` 同一文件 | 循环外一次读取或收集后一次 write | I/O 开销 | 代码审查 |
| `list.pop(0)` 作队列 | `collections.deque.popleft()`（`is_reachable` 已如此） | O(N) vs O(1) | 复用既有 |
| `subprocess.run` 无 `timeout` | 一律 `timeout=JOERN_TIMEOUT_SEC`（既有） | 防挂起 | 复用 `_run_joern_query` |
| 每次调用 `Path.exists()` 同一路径 | 缓存到局部变量 | syscall 开销 | 代码审查 |
| 正则 `CWE-\d+` 反复 `re.match` | 预编译 `_CWE_ID_RE` | 编译开销 | §4.1.2 |
| 无界 memo 增长 | `_TAINT_QUERY_MEMO_MAX = 512`，超出即清空（FIFO 不做 LRU，避免复杂度） | 防内存泄漏 | T2.8 |

### 0.5 错误处理规范

```python
# ✅ taint 链路唯一允许的失败形态: 降级为 verified=None + tier=0(或原 tier)
def verify_taint_flow(repo_root, sink_file, sink_line, language="python",
                      source_file=None, source_line=None):
    t0 = time.perf_counter()
    latency = lambda: int((time.perf_counter() - t0) * 1000)
    if not is_available():
        return {"verified": None, "evidence": "joern_unavailable",
                "tier": 0, "latency_ms": latency(),
                "taint_mode": None, "sink_nodes": 0, "source_nodes": 0}
    ...
```

- **不捕获 `Exception` 基类**：只捕获 `subprocess.TimeoutExpired` / `FileNotFoundError` / `OSError` / `SyntaxError`（与既有风格一致）。
- **调用方（`verify_l4_structural`）已用 `except Exception` 包裹 `joern_cpg` 调用**（[L350-L351](file:///f:/Coding/audit-driven-development/scripts/verify_findings.py#L350-L351) 既有模式），taint 沿用同一包裹 ⇒ `JOERN_FORCE_RAISE=1` 钩子可被捕获降级（AC-15）。
- **不使用 `logging` / 自定义异常类**（对齐 v2.8 实施规范 §0.5）。

def _extract_taint_cwe(evidence):
    """v3.0: 从**结构化字段** evidence["cwe"] 提取用于通道 A 判定的 CWE 标识.

    G-3 (Step 6 审计发现, v1.1 修正): **不做 claim 文本回退**。理由:
      (a) 设计 D-T9'-1 / AC-2 明确通道 A 只消费 `evidence.cwe` (结构化通道);

      claim 文本侧的 CWE 若需消费, 属通道 B 的职责。

    if not isinstance(evidence, dict):
        return ""
    cwe = evidence.get("cwe", "")
    if not cwe:
        return ""

```python
# 预编译（§0.4）: 从 claim 中提取"点分调用名"，如 subprocess.call / os.system / cursor.execute
_TAINT_SINK_RE = re.compile(r"([A-Za-z_]\w*(?:\.[A-Za-z_]\w*)*)\s*\(")

# 已知 sink 家族（用于从 claim 中优先识别，MVP 保守集合）
TAINT_SINK_HINTS = (
    "system", "popen", "call", "check_call", "check_output", "run", "Popen",
    "eval", "exec", "execfile", "compile",
    "execute", "executemany", "raw",
    "loads", "load", "load_all", "Unpickler", "read", "parse", "fromstring",
    "get", "post", "request", "urlopen", "send",
)


def _verify_taint_regex(claim, context_text, all_lines, line_num):
    """Tier 3 (regex): 验证 claim 断言的 sink API 是否存在于源码上下文.

    E-3 语义限定:
      仅当 sink 名由 **claim** 派生时, 才产出 True/False。
      若 claim 中无法派生 sink 名 => 返回 None (不写 check, D-T9'-5)。
      ⚠️ 不从"目标行"派生 sink 名: 目标行派生必然命中自身 => 恒 True => 自证陷阱。

    G-4 (Step 6 审计发现, v1.1 修正): all_lines / line_num 必须**被实际使用** ——
      否则是 dead parameter (本项目 v2.7.3 起持续追踪的反模式)。用途: 把目标行原文
      纳入 evidence 供人工复核 (**不参与 verified 判定**, 以保持 E-3 的语义限定)。
      签名保留 4 参数, 与同族 _verify_missing / _verify_import 保持同构。

    Returns:
        dict|None: {"verified": bool, "evidence": str, "sink_api": str,
                    "target_line": int, "target_text": str} 或 None
    """
    sink_api = ""
    for m in _TAINT_SINK_RE.finditer(claim or ""):
        cand = m.group(1)
        tail = cand.rsplit(".", 1)[-1]
        if tail in TAINT_SINK_HINTS:
            sink_api = cand
            break
    if not sink_api:
        return None                     # 无裁决 (E-3)
    found = sink_api in context_text or sink_api.rsplit(".", 1)[-1] in context_text
    # G-4: 消费 all_lines / line_num (仅供证据留痕, 不参与判定)
    target_text = all_lines[line_num - 1].strip() if 1 <= line_num <= len(all_lines) else ""
    return {"verified": bool(found),
            "evidence": f"regex: sink api '{sink_api}' "
                        f"{'present' if found else 'absent'} in source context; "
                        f"target line {line_num}: {target_text[:80]}",
            "sink_api": sink_api,
            "target_line": line_num,
            "target_text": target_text[:80]}
```
