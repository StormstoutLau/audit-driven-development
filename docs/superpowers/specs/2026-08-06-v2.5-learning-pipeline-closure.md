## 1. 问题陈述

### 1.1 核查发现的 6 个断点

v2.0-v2.3 宣称的"3 层学习管道 + 真实 RL loop"经源码核查（2026-08-06）发现**全部断裂**。6 个学习脚本存在但无调用关系：

| # | 脚本 | 断点类型 | 核查证据 |
|---|------|----------|----------|
| B1 | `rule_suggester.py` | 从未被管道调用 | grep `rule_suggester` 仅命中自身定义 + test_v21 字符串检查；`live_knowledge.py` steps 列表（L20-30）不含它 |
| B2 | `rule_validator.py` | 从未被管道调用 | grep `rule_validator` 仅命中自身定义；依赖 `rules.generalized.yml` 但该文件从不生成 |
| B3 | `fix_history.py` | threshold 无下游消费者 | `fix_history_meta` 写入 augmented_issues.json，但无脚本读取该 threshold；grep `default_threshold` 仅命中 fix_history 自身 |
| B4 | `llm_generalize.py` | 只建 prompt 不执行 | docstring L8-9 明确："This script builds the prompt. The main agent reads the output and dispatches a Subagent"——人工环节，从不自动触发 |
| B5 | `fix_recipes.py` | 只有 5 个硬编码 recipe | `--import-llm` 参数存在但 `recipes.generalized.yml` 从不生成（依赖 B4） |
| B6 | `verify_findings.py --hallucination-log` | 参数可选且从不被调用 | L698 `default=None`；`hallucination_log.json` 从未生成过文件（Glob 确认） |

**后果**：Phase 8 修复的 3 个 FP（classify_claim 误分类、ground truth 错误）本应被学习管道自动捕获，但因管道断裂，需手动发现。README 宣称的 recall 94.3% 虚高也是同一根因——没有闭环反馈，错误重复发生。

### 1.2 断裂拓扑图

```
当前状态 (v2.4-phase8):                           目标状态 (v2.5):
                                                 
  verify_findings ──(hallucination_log=None)──×   verify_findings ──(hallucination_log)──┐
                                                 │                                        │
  live_knowledge ──┬─ rule_extractor             │  live_knowledge ──┬─ rule_extractor    │
                   └─ spec_graph                  │                   ├─ spec_graph       │
                                                  │                   ├─ diff_miner        │
  diff_miner ───────× (standalone)                │                   ├─ fix_history ◄─────┤ threshold
  fix_history ──────× (threshold 无人读)          │                   ├─ rule_suggester ◄──┘ hallucination
  rule_suggester ───× (output 无人读)             │                   └─ benchmark_calibrate (新)
  rule_validator ───× (input 不生成)              │
  llm_generalize ───× (人工执行)                  │  rule_suggester ──► rule_suggestions.json
  fix_recipes ──────× (5 硬编码)                  │  fix_history ─────► threshold ──► verify_findings
                                                  │  benchmark ───────► regression check
                                                  └─► rule_validator (回滚标记)
```

### 1.3 目标

将 6 个断裂脚本接通为闭环，使框架具备：
1. **Hallucination → Detection 反馈**：verify_findings 移除的幻觉自动反馈给 rule_suggester 生成反例规则
2. **RL threshold → Verification 反馈**：fix_history 算出的 threshold 自动被 verify_findings 消费
3. **Benchmark → Self-calibration**：post-audit 自动跑 benchmark，recall 退化时触发告警

### 1.4 非目标

- **不**自动化 LLM generalization（B4）：保持人工 dispatch，因为 LLM 执行需要 Subagent 调度，超出脚本管道范围
- **不**生成 `rules.generalized.yml`：因此 rule_validator 暂不接入管道（保持 standalone）
- **不**改变现有 verify_findings 的 4 级验证逻辑：只接通数据流，不改动验证算法

**新增函数 `load_hallucinations`**：

```python
def load_hallucinations(log_path):
    """从 hallucination_log 加载幻觉模式，按 reason 聚类生成反例规则建议。

    触发条件：同类 reason 出现 >= min_frequency 次 → 生成反例规则。
    """
    p = Path(log_path)
    if not p.exists():
        return [], collections.Counter()
    try:
        data = json.loads(p.read_text(encoding="utf-8"))
    except (json.JSONDecodeError, ValueError):
        return [], collections.Counter()

    hallucinations = data.get("hallucinations", [])
    reason_counts = collections.Counter(
        h.get("reason", "unknown")[:80] for h in hallucinations
    )
    return hallucinations, reason_counts
```

**在 main() 中调用**：

```python
# 在现有 suggestions 构建之后追加
hallucinations, reason_counts = load_hallucinations(args.hallucination_log)
min_freq = args.min_frequency

hallucination_suggestions = [
    {
        "trigger": f"{count} hallucinations with reason: {reason}",
        "suggestion": f"Add guard: reject findings matching pattern '{reason[:60]}'",
        "action": "Review classify_claim() patterns for this failure mode",
        "source": "hallucination_log",
        "severity": "critical"
    }
    for reason, count in reason_counts.most_common()
    if count >= min_freq
]

suggestions += hallucination_suggestions
```

**验收标准**：
- 制造 3 个同类 reason 的 hallucination，跑 `rule_suggester --hallucination-log X --min-frequency 3`
- `rule_suggestions.json` 中出现 `source: "hallucination_log"` 的反例规则
- 跑 `live_knowledge` 端到端后，反例规则自动生成

### 2.3 阶段 3：Benchmark → Self-Calibration

**目标**：post-audit 自动跑 benchmark，recall 退化时触发告警。

#### 改动 3.1：run_phase8_benchmark.py 新增 --baseline 参数和退化检测

**新增参数**：
```python
parser.add_argument("--baseline", default=None,
                    help="Baseline performance JSON for regression comparison")
```

**新增函数 `check_regression`**：
```python
def check_regression(latest_data, baseline_data):
    """对比 latest 与 baseline，recall 退化 >5pp → REGRESSION 告警。

    Returns:
        dict: {"status": "OK"|"REGRESSION", "recall_delta": float,
               "precision_delta": float, "f1_delta": float,
               "action": str}
    """
    latest_agg = latest_data.get("aggregate", {})
    baseline_agg = baseline_data.get("aggregate", {})

    recall_delta = latest_agg.get("recall", 0) - baseline_agg.get("recall", 0)
    precision_delta = latest_agg.get("precision", 0) - baseline_agg.get("precision", 0)
    f1_delta = latest_agg.get("f1", 0) - baseline_agg.get("f1", 0)

    if recall_delta < -5.0:
        return {
            "status": "REGRESSION",
            "recall_delta": round(recall_delta, 1),
            "precision_delta": round(precision_delta, 1),
            "f1_delta": round(f1_delta, 1),
            "action": "Roll back recent rule changes; review rule_suggestions.json"
        }
    return {
        "status": "OK",
        "recall_delta": round(recall_delta, 1),
        "precision_delta": round(precision_delta, 1),
        "f1_delta": round(f1_delta, 1),
        "action": "No action needed"
    }
```

**在 main 末尾输出 regression check**：
```python
if args.baseline:
    baseline_data = json.loads(Path(args.baseline).read_text(encoding="utf-8"))
    regression = check_regression(output_data, baseline_data)
    output_data["regression_check"] = regression
    print(f"\n=== Regression Check ===")
    print(f"  Status: {regression['status']}")
    print(f"  Recall delta: {regression['recall_delta']}pp")
    if regression["status"] == "REGRESSION":
        print(f"  ⚠ ACTION: {regression['action']}")
```

- 手动注入一个会降低 recall 的规则变更（如弱化 classify_claim 的 pattern）
- 跑 `live_knowledge` 后 benchmark 步骤输出 `REGRESSION` 告警

## 3. 依赖关系与优先级

```
阶段 1 (接通管道) ──────► 阶段 2 (Hallucination 闭环) ──────► 阶段 3 (Self-Calibration)
  改动 1.1 + 1.2            改动 2.1 + 2.2                    改动 3.1 + 3.2
  ~30 行改动                ~50 行改动                         ~40 行改动
  必须先做                  依赖阶段 1 的 hallucination_log    依赖阶段 2 的反例规则
```

**阶段 1 是硬依赖**：没有 hallucination_log 生成，阶段 2 的 rule_suggester 无输入；没有 fix_history 被调用，阶段 2 的 threshold 无来源。

**阶段 3 可独立验证**：benchmark 退化检测不依赖阶段 2，但语义上应在阶段 2 之后（先有反馈闭环，再监控闭环健康度）。

## 4. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| live_knowledge 步骤增多导致延迟超标 | 中 | 中 | 每步 timeout=30s（现有），总上限 ~180s；diff_miner 已有 60s cap |
| fix_history 依赖 issues.json，首次运行不存在 | 高 | 低 | 改动 1.2 中标注 "FAIL 不阻塞后续"；live_knowledge 已有 per-step try/except |
| hallucination_log 首次为空，rule_suggester 无输入 | 高 | 低 | load_hallucinations 返回空列表，suggestions 为空，不报错 |
| benchmark_calibrate 耗时 175s（Phase 8 实测） | 高 | 中 | 设为可选步骤，`--skip-benchmark` flag；或单独 cron 触发 |
| threshold 反馈导致 verify_findings 行为漂移 | 中 | 高 | threshold 只影响相似度匹配（fix_history 内部），不改变 L4 结构化验证逻辑 |
