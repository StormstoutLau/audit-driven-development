## 1. 问题陈述

### 1.1 当前痛点

Phase 3.5 Finding Verification 的 L4 结构性验证使用正则启发式，准确率有限：

| L4 验证函数 | 当前方法 | 估计准确率 | 核心缺陷 |
|---|---|---|---|
| `_verify_dead_code` | 检查前一行是否是 return/raise | ~40% | 无 CFG，不处理分支/循环 |
| `_verify_import` | 正则匹配 import 语句存在性 | ~60% | 无图结构，无法检测循环依赖 |
| `_verify_missing` | 关键词不存在性检查 | ~50% | 无法判断"应该存在" |
| `_verify_wrong` | 关键词存在性检查 | ~40% | 无 ground truth 对比 |
| `_verify_violates` | 关键词存在性检查 | ~30% | 无形式化规约 |
| `_verify_generic` | 纯关键词匹配 | ~30% | 无结构验证能力 |

**整体 L4 准确率 ~42%**，意味着超过一半的 P0 claim 被错误地 confirmed 或 unconfirmed。

### 1.2 目标

引入 Joern CPG（Code Property Graph）作为 L4 的**高精度验证后端**，将 `dead_code` 和 `import_related` 两类 claim 的验证准确率从 ~40-60% 提升至 ~95%+。

### 1.3 为什么是 Joern 而非 CodeQL

| 维度 | CodeQL | Joern | Python ast 自建 |
|---|---|---|---|
| 许可证 | GitHub 专有（禁止商业代码） | **Apache-2.0（无限制）** | PSF（无限制） |
| CPG 完整度 | AST+CFG+DDG+污点追踪 | AST+CFG+PDG | 仅 AST（需自建 CFG） |
| Python 支持 | ✅ | ✅ (py2cpg) | ✅ |
| 可分发性 | ❌ 禁止 | ✅ 允许 | ✅ 允许 |
| 集成成本 | 低（但法律风险高） | 中（JDK 21 依赖） | 高（需自建 CFG） |
| 准确率 | ~99% | ~95% | ~90% |

**决策**: Joern 作为 Apache-2.0 许可证的 CPG 平台，是 CodeQL 的无限制等价替代。Python ast 作为零依赖 fallback。

## 2. 架构设计

### 2.1 三层验证架构

```
Phase 3.5 L4 结构性验证:
┌────────────────────────────────────────────────────────────────┐
│                        verify_findings.py                       │
│                                                                │
│  classify_claim(claim) → claim_types                           │
│                                                                │
│  ┌─ dead_code ──────────────────────────────────────┐          │
│  │  Tier 1: Joern CPG 可达性证明 (Apache-2.0)       │          │
│  │  Tier 2: Python ast CFG fallback (零依赖)         │          │
│  │  Tier 3: 正则启发式 (当前实现, 最终 fallback)     │          │
│  └──────────────────────────────────────────────────┘          │
│                                                                │
│  ┌─ import_related ─────────────────────────────────┐          │
│  │  Tier 1: Joern 导入图无环性证明 (Apache-2.0)     │          │
│  │  Tier 2: Python ast 导入图 fallback (零依赖)     │          │
│  │  Tier 3: 正则启发式 (当前实现, 最终 fallback)    │          │
│  └──────────────────────────────────────────────────┘          │
│                                                                │
│  ┌─ missing/wrong/violates/generic ─────────────────┐          │
│  │  正则启发式 (当前实现, 不变)                      │          │
│  └──────────────────────────────────────────────────┘          │
│                                                                │
│  Tier 1 结果 > Tier 2 > Tier 3 (优先级递减)                    │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 降级策略

```
Joern 可用？
  ├── Yes → Tier 1: Joern CPG 验证 (~95% 准确率)
  │         └── Joern 超时/错误？
  │             ├── Yes → 降级 Tier 2
  │             └── No → 返回结果
  │
  └── No → Python ast 可用？(总是可用，标准库)
            ├── Yes → Tier 2: Python ast CFG 验证 (~90% 准确率)
            │         └── 解析失败？
            │             ├── Yes → 降级 Tier 3
            │             └── No → 返回结果
            │
            └── No → Tier 3: 正则启发式 (~42% 准确率, 当前实现)
```

**关键原则**: 永远有 fallback，永远不因 Joern 不可用而崩溃。

### 2.3 数据流

```
被审计项目源码
      │
      ├──▶ joern_cpg.py                    (Tier 1)
      │    │  1. joern-parse → 生成 CPG 文件
      │    │  2. joern-query → 可达性/无环性查询
      │    │  3. 返回 {verified: bool, evidence: str, tier: 1}
      │    ▼
      ├──▶ ast_cfg.py  (新增)              (Tier 2)
      │    │  1. ast.parse() → AST
      │    │  2. 构建 CFG (if/for/try/while 分支)
      │    3. BFS 可达性检查
      │    │  4. 返回 {verified: bool, evidence: str, tier: 2}
      │    ▼
      └──▶ verify_findings.py 正则          (Tier 3, 当前实现)
           │  1. 正则匹配关键词
           │  2. 返回 {verified: bool, evidence: str, tier: 3}
           ▼
      合并结果 (Tier 1 > Tier 2 > Tier 3)
           │
           ▼
      Phase 4 修复基线 (幻觉已被拦截)
```

## 4. 模块详细设计

### 4.1 `joern_cpg.py` — Joern CPG 验证器 (Tier 1)

```
功能: 调用 Joern CLI 进行 CPG 级别的 claim 验证
依赖: Joern CLI (JDK 21+), Apache-2.0 许可证
输入:
  --repo <path>          被审计项目根目录
  --file <path>          claim 指向的文件
  --line <int>           claim 指向的行号
  --claim-type <str>     dead_code | import_related
  --claim <str>          原始 claim 文本
输出:
  JSON: {
    "verified": true|false|null,  # P0-2: null=None 表示该 Tier 无法判定, 触发降级
    "evidence": "Joern CPG: line 45 unreachable from entry (BFS traversal)",
    "tier": 1,
    "joern_version": "v4.0.553",
    "latency_ms": 1200
  }

逻辑:
  1. 检测 Joern 可用性: which joern-parse
     ├── 不可用 → 返回 {verified: None, tier: 0, reason: "joern_unavailable"}
     └── 可用 → 继续

  2. 生成 CPG (带缓存):
     joern-parse <repo> --output <tmp_dir>/cpg.bin
     缓存策略: 同一 repo 24h 内复用 CPG (基于 mtime hash, 非 git 项目也可用)

  3. 根据 claim_type 执行查询:

     dead_code 查询 (Scala DSL):
     ┌──────────────────────────────────────────────────────┐
     │ import io.joern.joerncli.*                            │
     │ import io.shiftleft.semanticcpg.*                     │
     │                                                       │
     │ @main def checkReachable(cpgFile: String, line: Int)  │
     │   val cpg = loadCpg(cpgFile)                          │
     │   val target = cpg.method.location.line(line).l       │
     │   val entry = cpg.method.callIn.l                     │
     │   val reachable = entry.reachableBy(target)           │
     │   println(s"reachable=${reachable.nonEmpty}")         │
     └──────────────────────────────────────────────────────┘

     import_related 查询:
     ┌──────────────────────────────────────────────────────┐
     │ import io.joern.joerncli.*                            │
     │ import io.shiftleft.semanticcpg.*                     │
     │                                                       │
     │ @main def checkCyclic(cpgFile: String) =              │
     │   val cpg = loadCpg(cpgFile)                          │
     │   val imports = cpg.imports.l                         │
     │   val graph = imports.foldLeft(Map.empty) {           │
     │     (g, imp) => g + (imp.file -> imp.imported)       │
     │   }                                                   │
     │   val hasCycle = detectCycle(graph)                   │
     │   println(s"has_cycle=${hasCycle}")                   │
     └──────────────────────────────────────────────────────┘

  4. 解析 Joern 输出，返回 JSON

超时: 30s (CPG 生成 + 查询)。超时 → 降级 Tier 2。
```

**Joern 版本要求**: v4.0+ (2026-06 最新 release: v4.0.553)
**JDK 要求**: JDK 21 (Joern v4.0 硬性要求)

### 4.2 `ast_cfg.py` — Python ast CFG 验证器 (Tier 2)

```
功能: 使用 Python 标准库 ast 模块构建 CFG，进行可达性和无环性验证
依赖: Python 3.8+ 标准库 (ast, collections, pathlib)，零外部依赖
输入:
  --repo <path>          被审计项目根目录
  --file <path>          claim 指向的文件
  --line <int>           claim 指向的行号
  --claim-type <str>     dead_code | import_related
  --claim <str>          原始 claim 文本
输出:
  JSON: {
    "verified": true|false|null,  # P0-2: null=None 表示无法判定, 触发降级
    "evidence": "ast CFG: line 45 unreachable (no path from entry)",
    "tier": 2,
    "ast_version": "Python 3.x",
    "latency_ms": 50
  }

逻辑:
  1. ast.parse(file_content) → AST 树

  2. CFG 构建 (CFGBuilder 类):
     遍历 AST 节点，为每个语句创建 CFG 节点和边:
     ├── FunctionDef → 入口节点 + 函数体 CFG
     ├── If → 条件节点 + then 分支 + else 分支 + 合并节点
     ├── For/While → 循环头 + 循环体 + 循环出口
     ├── Try → try 体 + except 分支(s) + else + finally
     ├── Return/Raise → 终止节点 (后续语句不可达)
     ├── With → 上下文管理器 + with 体
     ├── Match (3.10+) → 模式匹配分支
     └── 其他 → 顺序连接

     CFG 节点结构:
     @dataclass
     class CFGNode:
         line: int              # 源码行号
         stmt_type: str         # ast 节点类型
         successors: List[int]  # 后继节点 line 号

  3. dead_code 验证:
     a. 找到包含 line_num 的函数
     b. 从函数入口 BFS/DFS 遍历 CFG
     c. 如果 line_num 不可达 → verified=True (确实是 dead code)
     d. 如果可达 → verified=False (claim 是幻觉)

  4. import_related 验证 (循环依赖):
     a. 扫描项目所有 .py 文件的 import 语句
     b. 构建有向图: module_A → module_B (A imports B)
     c. DFS 检测环: 如果存在环 → verified=True (确实有循环依赖)
     d. 无环 → verified=False

超时: 5s (单文件 AST 解析 + CFG 遍历)。超时 → 降级 Tier 3。
```

**关键设计决策**:

| 决策点 | 选择 | 理由 |
|---|---|---|
| CFG 粒度 | 函数级 | 文件级 CFG 过于复杂，函数级足够验证 dead_code |
| 可达性算法 | BFS | 比 DFS 更适合证明不可达性（完备遍历） |
| import 图构建 | 静态分析 | 只扫描 `import x` / `from x import y`，不处理动态 import |
| 异步处理 | 同步 | P0 claim 数量少（通常 2-5 个），无需异步 |
| 缓存 | 不缓存 | 每次审计代码可能已变化，缓存会导致误判 |

### 6.2 性能优化策略

**CPG 缓存** (Tier 1 专用):
```
缓存目录: /tmp/add_joern_cache/
缓存键: sha256(repo_path + mtime_hash)  # P1-1: mtime hash, 非 git 项目也可用
        mtime_hash = sha256(sorted([(rel_path, mtime) for .py files]))[:16]
缓存有效期: 24h 或 .py 文件 mtime 变化
缓存命中: ~2s (仅查询)
缓存未命中: 5-30s (CPG 生成 + 查询)
```

**并行验证** (多 claim 场景):
```python
# 当前: 串行验证每个 claim
for finding in findings:
    verify(finding)

# 优化: 并行验证独立 claim (Tier 2/3, 不适用 Tier 1 因 Joern 单线程)
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor(max_workers=4) as pool:
    results = list(pool.map(verify, findings))
```
