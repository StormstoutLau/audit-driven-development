## 1. 问题陈述

### 1.1 v2.6 遗留的三个核心问题

v2.6 完成了数据集集成（687 findings 跨 6 个 benchmark），但暴露三个核心问题：

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| **P1** | 学习管道 5 个闭环断点 | benchmark→hallucination_log 路径断裂 / classify_claim 不读 rule_suggestions / 3 个学习脚本未接入 | 687 findings 的验证结果无法反馈到规则系统，学习管道空转 |
| **P2** | 610 条 finding 对 benchmark 零贡献 | Big-Vul 584 + CVEfixes 26 全部 `real_bug_no_repo` | 真实指标仅基于 77 条（27 Python + 50 Java），C/C++ 数据浪费 |
| **P3** | Java/C/C++ 不支持 L4 结构验证 | joern_cpg.py:615 硬编码 `pythonsrc` / ast_cfg.py 无扩展点 | Defects4J/Big-Vul/CVEfixes 仅跑 L1-L3，结构验证缺失 |

### 1.2 三个问题的依赖关系

```
P1 (闭环修复) ──→ P2 (数据补全) ──→ P3 (L4 扩展)
     │                  │                  │
     ▼                  ▼                  ▼
  v2.7.3            v2.7.2            v2.7.1
  (优先)            (依赖 v2.7.3)      (独立)
```

- **v2.7.3 必须先做**：hallucination_log 为空 → rule_suggester 无法生成规则 → classify_claim 无规则可消费。不修复闭环，数据补全的指标也无法反馈
- **v2.7.2 依赖 v2.7.3**：下载源码 repo 后，610 条 finding 进入指标计算，但验证结果需要通过闭环反馈到规则系统
- **v2.7.1 独立**：L4 多语言扩展是纯技术增强，不依赖闭环修复

### 1.3 目标

1. **v2.7.3 闭环修复**：打通 5 个断点，让 687 findings 的验证结果真正进入学习管道
2. **v2.7.2 数据补全**：下载 SWE-bench Verified + Big-Vul/CVEfixes 源码 repo，让 610+500 条 finding 进入指标计算
3. **v2.7.1 L4 扩展**：集成 javasrc2cpg/c2cpg Joern 前端，让 Java/C/C++ findings 支持 L4 结构验证

### 1.4 非目标

- **不**训练 ML 模型：仍然是规则 + 结构化验证系统
- **不**修改 L1-L3 验证算法：只修复闭环数据流和扩展 L4 语言支持
- **不**自动化 SWE-bench 的 HuggingFace 下载：提供下载指南，手动下载后运行转换脚本
- **不**为 Java/C++ 实现 Tier 2 (ast CFG)：Tier 2 仍仅支持 Python，Java/C++ 的 L4 依赖 Tier 1 (Joern) + Tier 3 (regex)

```python
def run_benchmark(test_config, hallucination_log_path=None):
```

```python
_LEARNED_RULES_CACHE = None

def _load_learned_rules(rules_path="docs/audit/rule_suggestions.json"):
    """v2.7.3: 加载 rule_suggestions.json 中的反例规则（带缓存）."""
    global _LEARNED_RULES_CACHE
    if _LEARNED_RULES_CACHE is not None:
        return _LEARNED_RULES_CACHE
    path = Path(rules_path)
    if not path.exists():
        _LEARNED_RULES_CACHE = []
        return _LEARNED_RULES_CACHE
    data = json.loads(path.read_text(encoding="utf-8"))
    _LEARNED_RULES_CACHE = data.get("suggestions", [])
    return _LEARNED_RULES_CACHE

def classify_claim(claim, evidence):
    # ... 现有 regex 分类逻辑 ...
    
    # v2.7.3 断点③修复：检查反例规则
    learned_rules = _load_learned_rules()
    for rule in learned_rules:
        reason = rule.get("reason", "")
        if reason and reason[:60] in claim:
            # 匹配到反例规则 → 降级 severity
            return "generic", rule  # 返回 rule 供调用方降级
    
    return claim_type, None
```

```python
def download_repo(repo_url, commit_hash, dest_dir):
    """下载指定 commit 的源码 repo.
    
    策略:
      1. git clone --depth 1 <repo_url> <dest_dir>
      2. cd <dest_dir> && git fetch --depth 1 origin <commit_hash>
      3. git checkout <commit_hash>
    
    失败处理:
```

### 10.4 设计决策记录

| 决策 | 理由 |
|------|------|
| `_generate_cpg` 接收映射后的 Joern 语言名 (如 `pythonsrc`)，脚本生成器接收内部语言名 (如 `python`) | `_generate_cpg` 需要 Joern 前端名来构建命令；脚本生成器需要内部名来选择后缀剥离逻辑 |
| `_JOERN_LANGUAGE_MAP` (verify_findings.py) 和 `JOERN_LANGUAGE_MAP` (joern_cpg.py) 并行存在 | verify_findings.py 的映射用于潜在的前端选择；joern_cpg.py 的映射是实际使用的权威映射 |
| Tier 2 (ast CFG) 仅支持 Python | Java/C++ 的 AST 解析需要对应语言的 parser (javalang/pycparser)，当前不引入新依赖 |
| `cpg.method.lineNumber(N)` 跨语言通用 | METHOD 是 Joern universal node type，pythonsrc/javasrc2cpg/c2cpg 前端均生成 METHOD 节点 |
| `l4_eligible` 默认 True | 向后兼容：现有 findings 无此字段时默认跑 L4 |
