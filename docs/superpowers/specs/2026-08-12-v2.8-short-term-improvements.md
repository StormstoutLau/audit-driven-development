## 2. 任务详细设计

### 2.1 T1 — `_history_threshold` 真正驱动 L1-L4 验证行为

#### 2.1.1 当前状态 (代码证据)

- `verify_findings.py` L686-L711: `history_threshold` 参数仅写入 `f["_history_threshold"]` 字段
- `verify_findings.py` L832-L842: `effective_threshold` 从 `augmented_issues.json` 的 `fix_history_meta.threshold_used` 加载
- `fix_history.py` L103-L109: threshold 根据 scores.json trend 动态调整 (▲→0.55, ▼→0.85)
- **断点**: threshold 加载后未驱动任何验证逻辑

#### 2.1.2 设计方案

**threshold 影响点**: L3 keyword matching 的 `confirmed` 判定

当前 L3 逻辑 (已读取 `verify_findings.py` L198-L222 实际代码):
- L3: Keyword/pattern match in source context (±20 lines)
- `verify_l3(lines, line_num, keywords)` 函数: 先在 target_line 精确匹配，再在 ±20 行邻近窗口内匹配
- `confirmed = True` 当且仅当至少 1 个 keyword 在窗口内匹配 (使用 `next()` 找到第一个即返回)

**threshold 驱动方案**:
- `threshold` 表示 L3 confirmed 所需的最小 keyword 匹配数
- threshold=0.55 (improving, 宽松) → minimum_keywords=1 (当前行为)
- threshold=0.65 (default) → minimum_keywords=1 (当前行为)
- threshold=0.85 (declining, 严格) → minimum_keywords=2 (提高门槛)

**映射函数**:
```python
def _threshold_to_min_keywords(threshold):
    """v2.8: 将 RL-adjusted threshold 映射到 L3 最小 keyword 匹配数.

    threshold ∈ [0.55, 0.85]:
      - [0.55, 0.75) → min_keywords=1 (宽松, improving trend)
      - [0.75, 0.85] → min_keywords=2 (严格, declining trend)
      - None         → min_keywords=1 (默认, 向后兼容)
    """
    if threshold is None:
        return 1
    if threshold >= 0.75:
        return 2
    return 1
```

**修改点**:
1. `verify_l3()` 新增 `min_keywords=1` 参数
2. `verify_single_finding()` 读取 `finding.get("_history_threshold")`，调用 `_threshold_to_min_keywords()`，传入 `verify_l3()`
3. `verify_all_findings()` 保持当前写入 `_history_threshold` 的行为

**向后兼容**: threshold=None 时 min_keywords=1，与 v2.7 行为一致

#### 2.1.3 RL 闭环验证

```
scores.json trend ▼ (declining)
    │
    ▼ fix_history.py
threshold_used = 0.85
    │
    ▼ verify_findings.py main() L832-L842
effective_threshold = 0.85
    │
    ▼ verify_all_findings() L709-L711
f["_history_threshold"] = 0.85
    │
    ▼ verify_single_finding() [v2.8 新增]
min_keywords = _threshold_to_min_keywords(0.85) = 2
    │
    ▼ verify_l3(min_keywords=2) [v2.8 新增]
L3 confirmed 需要 >= 2 keywords 匹配
    │
    ▼ 更多 findings 因 L3 失败被标记为 hallucination
hallucination_log 增长
    │
    ▼ rule_suggester 生成更多反例规则
rule_suggestions.json 扩充
    │
    ▼ 下一轮 benchmark 指标变化 (闭环完成)
```

### 2.2 T3 — `semgrep_to_findings.py` 转换器

#### 2.2.2 Semgrep JSON 输出格式 (基于官方文档)

> **源**: https://semgrep.dev/docs/semgrep-appsec-platform/json-and-sarif (原 https://semgrep.dev/docs/cli-reference/json-output/ 已 404)

Semgrep `--json` 输出结构:
```json
{
  "results": [
    {
      "check_id": "python.lang.security.audit.dangerous-subprocess-use",
      "path": "src/main.py",
      "start": {"line": 42, "col": 5},
      "end": {"line": 42, "col": 50},
      "extra": {
        "message": "Dangerous subprocess use",
        "severity": "ERROR",
        "metadata": {
          "cwe": ["CWE-78: Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')"],
          "owasp": ["A1: Injection"]
        }
      }
    }
  ]
}
```

> **注意**: `extra.metadata.cwe` 和 `extra.metadata.owasp` 是**数组类型** (非字符串)，转换器需处理数组 (取第一个元素或 join)

#### 2.2.3 设计方案

**新建文件**: `scripts/semgrep_to_findings.py`

**转换映射**:

| Semgrep 字段 | ADD finding 字段 | 说明 |
|---|---|---|
| `check_id` | `id` (前缀 SG-) | 规则 ID → finding ID |
| `extra.severity` (ERROR/WARNING/INFO) | `severity` (P0/P1/P2) | ERROR→P0, WARNING→P1, INFO→P2 |
| `path` | `evidence.file` | 文件路径 |
| `start.line` | `evidence.line_start` | 起始行 |
| `extra.message` + `check_id` | `claim` | 组合成 claim 文本 |
| `extra.metadata.cwe` (数组) | `evidence.cwe` | CWE 标识 (取数组第一个元素或 join) |
| `extra.metadata.owasp` (数组) | `evidence.owasp` | OWASP 分类 (同上) |
| (无对应) | `l4_eligible=True` | Semgrep findings 默认跑 L4 |
| (无对应) | `dimension="security"` | 安全维度 |

**Claim 模板**:
```
{check_id}: {message} ({cwe}) — affects {path}:{line}
```

**CLI 接口** (与现有转换器一致):
```bash
python scripts/semgrep_to_findings.py <semgrep-output.json> \
    --output <output_dir> \
    [--repo-local-path <path>]  # 可选, 用于 L4 验证
```

**输出**: `findings.json` + `ground_truth.json` (所有 findings 标记为 `real_bug_pending_verification`，因 Semgrep findings 并非 100% 真实，需经 ADD L1-L4 验证后才能确认为 `real_bug`)

### 2.3 T4 — `codeql_to_findings.py` 转换器 (SARIF)

#### 2.3.1 当前状态

- 无 `codeql_to_findings.py` — 需新建

#### 2.3.2 SARIF 格式 (基于 OASIS 标准 + Microsoft SARIF Tutorials)

> **源**: https://github.com/microsoft/sarif-tutorials (SARIF 规范共同编辑 Larry Golding 撰写)
> **注意**: `properties.tags` 是 SARIF 的 property bag 机制，标签内容**由工具自行约定**，SARIF 规范不强制要求 `cwe` 标签必须存在。CodeQL 在实践中会在 tags 中输出 `external/cwe/cwe-78` 等标签，但这是 CodeQL 的实现选择，非 SARIF 强制。

CodeQL `--format sarif-latest` 输出结构:
```json
{
  "runs": [
    {
      "results": [
        {
          "ruleId": "py/command-injection",
          "level": "error",
          "locations": [
            {
              "physicalLocation": {
                "artifactLocation": {"uri": "src/main.py"},
                "region": {"startLine": 42}
              }
            }
          ],
          "message": {"text": "Command injection"}
        }
      ],
      "tool": {
        "driver": {
          "rules": [
            {
              "id": "py/command-injection",
              "properties": {"tags": ["security", "external/cwe/cwe-78"]}
            }
          ]
        }
      }
    }
  ]
}
```

#### 2.3.3 设计方案

**新建文件**: `scripts/codeql_to_findings.py`

**转换映射**:

| SARIF 字段 | ADD finding 字段 |
|---|---|
| `ruleId` | `id` (前缀 QL-) + `evidence.rule_id` |
| `level` (error/warning/note) | `severity` (error→P0, warning→P1, note→P2) |
| `locations[0].physicalLocation.artifactLocation.uri` | `evidence.file` |
| `locations[0].physicalLocation.region.startLine` | `evidence.line_start` |
| `message.text` + `ruleId` | `claim` |
| `tool.driver.rules[i].properties.tags` (CodeQL 约定含 `external/cwe/cwe-*`) | `evidence.cwe` (需过滤含 `cwe` 的 tag，若无则为空) |
| (无对应) | `l4_eligible=True` |
| (无对应) | `dimension="security"` |

**Claim 模板**:
```
{ruleId}: {message_text} ({cwe_tags}) — affects {uri}:{startLine}
```

**CLI 接口** (与 T3 一致):
```bash
python scripts/codeql_to_findings.py <codeql-output.sarif> \
    --output <output_dir> \
    [--repo-local-path <path>]
```

# CWE Top 25 (2023) — MITRE 官方排名

CWE_TOP_25_2023 = {

**功能**:
1. `enrich_finding_with_cwe(finding)`: 如果 finding 的 claim/evidence 含 CWE-XX，添加 `evidence.cwe_rank` 和 `evidence.cwe_category` 字段

#### 2.5.2 设计方案

**新建文件**: `.github/workflows/add-audit.yml`

> **⚠️ Semgrep Action 迁移提示** (2026-08-12 校验):
> - `returntocorp/semgrep-action@v1` 已被 Semgrep 官方标记为 **frozen/deprecated**，仅接收关键修复，不再推荐用于新部署 (见 https://github.com/returntocorp/semgrep-action README)
> - **迁移路径**: 改用官方推荐的 `semgrep/semgrep` 直接调用 Semgrep CLI，或 `docker run --rm -v "${PWD}:/src" returntocorp/semgrep:latest`
> - 下方 workflow 已采用迁移后的 **`semgrep/semgrep`** action

**Workflow 流程**:
```yaml
name: ADD Audit (Semgrep → ADD Verification)

on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]

jobs:
  add-audit:
    runs-on: ubuntu-latest
    steps:
      # 1. Checkout
      - uses: actions/checkout@v4

      # 2. Run Semgrep (CE, free) — 使用官方 semgrep/semgrep action
      #    迁移自 returntocorp/semgrep-action@v1 (frozen, 不再推荐)
      - name: Semgrep Scan
        uses: semgrep/semgrep@v1
        with:
          config: >-
            p/python
            p/owasp-top-ten
            p/cwe-top-25
          output: semgrep-results.json

      # 3. Convert Semgrep → ADD findings
      - name: Convert Semgrep to ADD findings
        run: |
          python scripts/semgrep_to_findings.py semgrep-results.json \
              --output docs/benchmark/semgrep-ci \
              --repo-local-path .

      # 4. Run ADD Verification (L1-L4)
      - name: ADD Phase 3.5 Verification
        run: |
          python scripts/verify_findings.py \
              --findings docs/benchmark/semgrep-ci/findings.json \
              --repo . \
              --output docs/audit/verified.json \
              --hallucination-log docs/audit/hallucination_log.json

      # 5. Upload results
      - uses: actions/upload-artifact@v4
        with:
          name: add-audit-results
          path: |
            docs/audit/verified.json
            docs/audit/hallucination_log.json
```

**关键设计**:
- 使用 Semgrep CE (免费) 产出候选 findings
- ADD 作为下游过滤器，用 4 级验证门过滤幻觉
- 上传 verified.json + hallucination_log.json 作为 artifact
- **Semgrep Action 选择**: 采用 `semgrep/semgrep@v1` (官方推荐)，废弃 `returntocorp/semgrep-action@v1` (frozen)。如需回退方案，可使用 `docker run returntocorp/semgrep:latest semgrep scan --config p/python --json > semgrep-results.json`
